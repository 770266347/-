# 《垃圾收集者》策划案与系统拆分

## 1. 游戏定位

《垃圾收集者》是一款竖屏轻量增量游戏。

玩家从街道上手动捡塑料瓶开始，获得瓶子和现金；随后购买帮手、升级工具、解锁区域和回收站能力，逐步从“一个人捡瓶子”成长为“街区环保回收事业”。

核心体验关键词：

- 轻松
- 可爱
- 成长感明确
- 点击反馈爽
- 数值滚雪球
- 适合小程序碎片时间游玩

## 2. 核心循环

第一版核心循环只保留一条主线：

1. 街道中自动刷新可点击塑料瓶。
2. 玩家点击瓶子。
3. 获得 `塑料瓶` 和 `现金`。
4. 用现金购买帮手或升级。
5. 帮手提高自动捡瓶效率。
6. 升级提高每瓶收益或自动效率。
7. 继续积累，解锁下一个系统。

当前基础规则：

- 点击 1 个瓶子：获得 `+1 塑料瓶` 和 `+1 元`。
- 帮手：提供每秒自动捡瓶。
- 升级：提高每瓶收益或自动捡瓶效率。

## 3. 第一阶段 MVP 系统

第一阶段目标是把游戏框架稳定下来，而不是扩很多内容。

第一阶段各系统会拆到 `策划案/` 文件夹单独维护。核心玩法系统详见：`策划案/01_核心玩法系统策划案.md`。

### 3.1 资源系统

必须有：

- `塑料瓶`：累计收集数量，体现主题和进度。
- `现金`：购买帮手、升级、解锁内容的主要货币。
- `每秒捡瓶`：自动化效率指标。

暂不做：

- 多垃圾类型
- 声望
- 环保值
- 钻石/广告币
- 离线收益上限

### 3.2 场景掉落系统

必须有：

- 中间街道区域刷新瓶子。
- 瓶子可点击。
- 瓶子大小、数量、刷新频率可配置。
- 可点击瓶子需要和背景明显区分。

后续可扩展：

- 不同垃圾：塑料瓶、易拉罐、纸箱。
- 稀有掉落：红包瓶、金色瓶。
- 连点反馈：连击、暴击、飘字。

### 3.3 帮手系统

定位：自动化收益系统。

第一版帮手：

- 热心邻居
- 二手小推车
- 社区回收箱

每个帮手需要配置：

- 名称
- 描述
- 基础每秒产出
- 初始价格
- 价格成长倍率
- 当前等级

第一阶段只做“购买后提高每秒捡瓶”，不做帮手上场动画。

### 3.4 升级系统

定位：永久倍率成长。

第一版升级：

- 识瓶眼力：提高每瓶现金收益。
- 回收路线：提高自动捡瓶效率。

每个升级需要配置：

- 名称
- 描述
- 最大等级
- 初始价格
- 价格成长倍率
- 效果类型
- 每级效果值

第一阶段只做数值效果，不做复杂技能树。

### 3.5 存档系统

必须有：

- 自动保存
- 手动保存
- 重置存档
- 存档版本号
- 后续可迁移

需要存：

- 当前现金
- 当前塑料瓶
- 累计塑料瓶
- 帮手等级
- 升级等级

暂不做：

- 云存档
- 账号绑定
- 跨设备同步

### 3.6 主界面 UI

第一阶段主界面结构：

- 顶部：资源栏，显示成长、现金、瓶子、每秒收益。
- 中间：街道场景，可点击瓶子。
- 右侧：功能入口占位，暂时只做按钮外观。
- 底部：物品/技能标签和升级卡片。

UI 原则：

- 所有能点击的东西要比背景更亮、更清楚。
- 背景不能出现和可点击物混淆的静态瓶子。
- 文字要少，按钮要大，适合手机点击。
- 先保证可用，再逐步美化。

## 4. 第二阶段扩展系统

第二阶段是在核心循环稳定后再做。

### 4.1 地区系统

用途：提供中期目标。

可解锁区域：

- 小区门口
- 商业街
- 公园
- 夜市
- 海边步道

每个区域可以影响：

- 背景图
- 刷新速度
- 稀有掉落概率
- 解锁新帮手
- 解锁新升级

### 4.2 任务系统

用途：引导玩家，不让玩家只盯着数字。

任务类型：

- 收集 N 个瓶子
- 拥有 N 元现金
- 购买某个帮手
- 升级某项能力到 N 级

奖励：

- 现金
- 一次性瓶子
- 区域解锁进度

### 4.3 成就系统

用途：长期目标和轻量留存。

成就例子：

- 第一次捡瓶
- 累计捡 100 个瓶子
- 第一次购买帮手
- 每秒捡瓶达到 10

第一版只需要弹提示和记录状态，不需要复杂成就页。

### 4.4 离线收益

用途：增量游戏基本预期。

规则建议：

- 离线时按当前自动捡瓶效率计算。
- 第一版最多累计 2 小时。
- 回来后弹窗结算。

注意：离线收益要等核心数值稳定后再加，否则容易把经济打乱。

## 5. 第三阶段商业化/小程序系统

这些系统先设计边界，不急着做。

### 5.1 广告激励

可做入口：

- 双倍离线收益
- 临时提高瓶子价值
- 获得一次稀有瓶雨

注意：广告逻辑必须走 `PlatformBridge`，不要写进玩法系统。

### 5.2 分享系统

可做入口：

- 分享获得一次小额现金
- 分享解锁装饰
- 分享邀请好友榜

### 5.3 排行榜

可排行：

- 累计瓶子
- 当前现金
- 每秒收益

### 5.4 云存档

等账号体系确定后再做。

## 6. 暂时不要做的系统

这些容易让项目变乱，先不要碰：

- 多角色养成
- 装备系统
- 复杂地图移动
- 剧情系统
- 付费商城
- 抽卡
- 多货币经济
- 复杂技能树
- 联机或好友实时互动

## 7. 推荐开发顺序

### 阶段 A：框架稳定

目标：让现在的核心循环干净、稳定、能玩 5 分钟。

任务：

1. 梳理 `GameState`，明确资源字段。
2. 把瓶子刷新参数配置化。
3. 把帮手配置表扩成更完整的 5-8 个。
4. 把升级配置表扩成 5-8 个。
5. 做一个统一的购买卡片 UI。
6. 增加简单任务入口，但可以先不实现完整任务。

验收：

- 开局 30 秒内能买第一个东西。
- 3 分钟内能感到自动收益变强。
- 5 分钟内至少有 2-3 个明确目标。

### 阶段 B：内容扩展

目标：让玩家有中期目标。

任务：

1. 加地区系统。
2. 加任务系统。
3. 加成就提示。
4. 加离线收益。

验收：

- 玩家知道下一个区域怎么解锁。
- 离开回来有收益。
- 有持续目标，不只是反复点瓶子。

### 阶段 C：小程序准备

目标：准备发行边界。

任务：

1. 接入 `PlatformBridge` 的小程序生命周期。
2. 接入广告占位。
3. 接入分享占位。
4. 做性能和包体检查。
5. 做真机分辨率适配检查。

## 8. 当前代码和策划的对应关系

当前已经有：

- `GameState`：资源和等级状态。
- `ProductionSystem`：点击瓶子和自动收益。
- `GeneratorSystem`：帮手购买。
- `UpgradeSystem`：升级购买。
- `BottleSpawnArea`：街道中刷新可点击瓶子。
- `HUD`：主界面资源和功能入口。
- `SaveManager`：本地存档。
- `PlatformBridge`：平台边界。

下一步最应该补：

1. 瓶子刷新配置表。
2. 统一购买卡片 UI。
3. 任务系统骨架。
4. 地区系统骨架。
