# 01_核心玩法系统需求点

## 1. 系统目标

核心玩法系统只负责一件事：

> 玩家在街道中点击可拾取物，获得塑料瓶和现金。

## 2. 玩家操作需求

- 玩家可以在主界面中间街道区域看到可点击塑料瓶。
- 玩家点击塑料瓶后，塑料瓶立即被收集。
- 玩家点击空白街道区域时，不产生收益。
- 玩家可以连续点击多个瓶子。
- 玩家不需要进入二级界面即可完成核心操作。

## 3. 瓶子刷新需求

- 街道区域会自动刷新塑料瓶。
- 刷新位置必须在可见街道区域内。
- 刷新位置不能被顶部资源栏、右侧按钮、底部面板明显遮挡。
- 同屏瓶子数量有上限。
- 刷新间隔有随机范围，避免固定节奏太机械。
- 瓶子被点击后，从同屏数量中移除。
- 瓶子不会自动过期消失，除非后续版本另行设计。

## 4. 基础数值需求

第一版固定规则：

| 项目 | 数值 |
|---|---:|
| 点击 1 个瓶子获得塑料瓶 | 1 |
| 点击 1 个瓶子获得现金 | 1 元 |
| 初始每瓶现金价值 | 1 元 |

推荐刷新参数：

| 项目 | 建议值 |
|---|---:|
| 最小刷新间隔 | 0.65 秒 |
| 最大刷新间隔 | 1.25 秒 |
| 同屏最大瓶子数量 | 9 |
| 瓶子尺寸 | 44x64 pt |
| 高亮圈倍率 | 1.16 |

## 5. 资源变化需求

点击瓶子后需要同时更新：

- 当前塑料瓶数量
- 累计塑料瓶数量
- 当前现金
- 累计获得现金

点击收益计算：

```text
本次现金收益 = 本次获得瓶子数 * 每瓶现金价值
```

第一版：

```text
1 * 1 = 1 元
```

## 6. 视觉需求

### 6.1 背景

- 背景是干净街道。
- 背景不能出现静态塑料瓶。
- 背景不能出现静态硬币、奖励物、发光物。
- 背景可以出现回收桶、树、商店、路面、绿植。
- 背景不能让玩家误判哪些东西能点。

当前背景素材：

```text
assets/street_pickup_bg_clean.png
```

### 6.2 可点击瓶子

- 可点击瓶子必须明显区别于背景。
- 瓶子可以有轻微高亮圈。
- 瓶子不能太大，避免挡住街道。
- 瓶子不能太小，避免手机上难点。
- 瓶子点击区域应和视觉大小基本一致。

当前瓶子素材：

```text
assets/bottle.svg
```

## 7. 点击反馈需求

点击成功后必须有反馈：

- 瓶子消失。
- 播放短动画。
- 出现飘字。
- 顶部资源数字刷新。

飘字内容：

```text
+1 瓶 +1 元
```

动画建议：

| 项目 | 建议值 |
|---|---:|
| 瓶子消失动画 | 0.16 秒 |
| 飘字持续时间 | 0.48 秒 |
| 飘字方向 | 向上淡出 |

## 8. 配置化需求

核心玩法参数不能长期硬编码在脚本中。

建议新增配置：

```text
data/drop_config.json
```

配置内容：

```json
{
  "bottle": {
    "reward_bottles": 1,
    "base_cash_value": 1.0,
    "spawn_interval_min": 0.65,
    "spawn_interval_max": 1.25,
    "max_inventory": 1000,
    "max_on_screen": 90,
    "size_pt": [44, 64],
    "glow_scale": 1.16
  }
}
```

## 9. 代码需求

需要支持：

- `ConfigDB` 读取 `drop_config.json`。
- `BottleSpawnArea` 从配置读取刷新参数。
- `BottleSpawnArea` 从配置读取瓶子尺寸和高亮倍率。
- `GameState` 从配置读取基础每瓶现金价值。
- 点击瓶子时统一调用收益发放逻辑。
- 点击收益逻辑不能散落在 UI 脚本中。

## 10. 验收需求

功能验收：

- 进入游戏后，街道区域能自动刷新瓶子。
- 点击瓶子后，瓶子消失。
- 点击瓶子后，塑料瓶数量 +1。
- 点击瓶子后，现金 +1 元。
- 同屏瓶子数量不超过上限。
- 背景中没有会混淆的静态瓶子。

手感验收：

- 玩家第一眼能看出瓶子可以点击。
- 点击反馈足够快。
- 瓶子大小适合手机点击。
- 30 秒内玩家能通过点击获得明显收益。

技术验收：

- Godot editor 加载无报错。
- 掉落参数来自配置文件。
- 修改配置后不需要改脚本即可调整瓶子刷新和收益。
