# 04_帮手系统需求点

## 1. 系统目标

帮手系统负责决定：

> 玩家解锁帮手后，帮手会进入当前场景走动，并自动帮玩家收集场景中的回收物。

第一版帮手系统只做“自动走动 + 自动拾取”，不先做复杂 AI。

## 2. 帮手基础需求

- 玩家可以通过升级或购买解锁帮手。
- 解锁后的帮手会显示在当前场景中。
- 帮手会在场景区域内自动走动。
- 帮手会自动寻找可收集回收物。
- 帮手收集成功后，玩家获得对应回收物和现金。
- 帮手不能收集尚未解锁的产物。
- 场景切换时，全部已上阵帮手通过传送门进入新场景后继续工作。

## 3. 帮手行为需求

帮手第一版使用简单行为循环：

```text
待机 -> 寻找目标 -> 移动到目标 -> 收集目标 -> 继续寻找
```

### 3.1 待机

- 当前场景没有可收集目标时，帮手在场景内随机走动。
- 待机时可以播放轻微左右晃动或走路动画。
- 待机时间不需要太长，避免玩家觉得帮手没在工作。

### 3.2 寻找目标

- 帮手优先寻找距离最近的可收集产物。
- 帮手选中目标时，需要立即预约该产物。
- 已经被其他帮手预约的产物不能再次成为目标。
- 预约在产物被拾取、被玩家提前点击、帮手下阵或场景切换时释放。
- 如果没有目标，继续待机。
- 如果目标已经被玩家点击收走，帮手重新寻找目标。

### 3.3 移动到目标

- 帮手朝目标位置移动。
- 移动速度由帮手配置决定。
- 帮手不能走出可见场景区域。
- 帮手移动过程中不阻挡玩家点击。

### 3.4 收集目标

- 帮手靠近目标后自动收集。
- 目标被收集后消失。
- 玩家获得该目标对应收益。
- 出现飘字反馈。
- 帮手收集和玩家点击使用同一套收益发放逻辑。

## 4. 帮手解锁需求

- 每个帮手有独立解锁条件。
- 帮手解锁条件可以包含指定产物的终身累计收集数量。
- 多个产物数量条件同时存在时，必须全部满足才允许购买。
- 帮手系统通过产物 ID 查询 `GameState` 分类统计，不能依赖弹窗文本。
- 未解锁帮手不显示在场景中。
- 已解锁帮手不能重复解锁。
- 解锁成功后，帮手默认上阵并立即进入当前场景。
- 已购买帮手可以手动上阵或下阵。
- 购买状态和上阵状态都需要存档。

美术约束：

- 每个帮手必须有明显不同的整体轮廓，缩小到当前场景显示尺寸后仍能辨认。
- 人物保持正常卡通比例，通过帽子、服装、背包、推车等装备形成差异。
- 单个角色最多突出两件核心装备，避免小尺寸下细节混乱。
- 表情自然友善，不使用夸张怪异的五官或肢体设计。
- 颜色需要覆盖黄、绿、红、青、灰等不同色系，避免十名帮手挤在一起时无法区分。
- 所有角色至少需要待机、移动、拾取、进入传送门和离开传送门五类表现。

当前不限制上阵数量。玩家可以在帮手页签中逐个下阵暂时不用的帮手，从而减少画面遮挡或控制自动拾取速度。

## 5. 帮手能力需求

每个帮手需要配置：

- 帮手 ID
- 显示名称
- 解锁费用
- 移动速度
- 收集半径
- 收集冷却
- 可工作的场景；空数组表示全部场景
- 优先收集类型；空数组表示全部类型
- 视觉素材
- 防守玩法圆形攻击半径 `defense_range`；该数值与回收玩法的 `collect_radius` 相互独立

正式参数以 `4.1 通用帮手角色设计` 中的数值表为准。

## 6. 全场景与传送门切换需求

- 只有已上阵帮手会在全部场景显示并工作。
- 已下阵帮手不生成场景角色，不自动拾取，也不参与传送门过场。
- 帮手可以收集当前场景中任意已经解锁的产物类型。
- 玩家请求切换场景后，暂时停止产物刷新和帮手自动拾取。
- 传送门方向由目标场景相对位置决定：向右切换时在右侧生成，向左切换时在左侧生成。
- 所有帮手走向切换方向一侧的传送门，并在到达后消失。
- 所有帮手进入后才正式切换场景背景和产物池。
- 新场景在相反侧边缘生成传送门：向右切换时从左侧进入，向左切换时从右侧进入。
- 帮手从传送门依次出现，走到场景内部后恢复自动拾取。
- 过场期间左右场景切换按钮不可重复点击。
- 没有购买帮手时，仍显示短暂的传送门过场后切换场景。

## 7. 自动拾取规则需求

- 帮手只能拾取当前场景中已经生成的产物。
- 帮手不能凭空产出收益。
- 帮手收集目标后，该目标从画面中移除。
- 帮手和玩家同时点击同一个目标时，只能结算一次。
- 多个帮手同时寻找目标时，每个产物最多只能被一个帮手预约。
- 帮手拾取收益和玩家点击收益一致。
- 帮手拾取也会计入累计回收物和累计现金。

## 8. UI 需求

主界面下方显示页签栏。

页签栏包含：

- `升级`
- `场景`
- `帮手`

`帮手` 页签需要显示不同帮手的购买按钮。

- 未购买帮手显示整行购买按钮。
- 已购买帮手在条目右侧显示独立的 `下阵` 或 `上阵` 按钮。
- 点击 `下阵` 后，帮手从当前场景移除，按钮变为 `上阵`。
- 点击 `上阵` 后，帮手进入当前场景工作，按钮变为 `下阵`。
- 场景传送过程中暂时禁用上下阵按钮。
- 帮手列表支持鼠标和触摸上下滑动。
- 从条目信息区、购买按钮或上下阵按钮上按住拖动，都可以滚动列表。
- 手指或鼠标移动超过拖动阈值后取消本次按钮点击，避免滑动时误购买或误切换上下阵。

帮手购买按钮需要显示：

- 帮手名称
- 解锁费用
- 当前状态
- 工作场景
- 简单能力描述

按钮尺寸要求：

- 按钮尽量小。
- 单个按钮高度不宜过高。
- 文案优先短句，避免把底部面板撑得太高。
- 竖屏下至少能同时看到 3 个帮手按钮。

帮手状态：

| 状态 | 显示含义 |
|---|---|
| 未解锁 | 可以购买或条件不足 |
| 已解锁 | 帮手已拥有 |
| 工作中 | 帮手正在当前场景工作 |
| 已下阵 | 帮手已拥有，但当前不生成也不工作 |

## 10. 存档需求

存档中需要记录：

- 已解锁帮手 ID 列表
- 帮手是否已购买
- 已购买帮手的上阵状态
- 各产物终身累计收集数量；该数据由核心玩法存档，帮手系统只读取

不需要存档：

- 帮手当前坐标
- 帮手当前目标
- 帮手当前动画状态

这些运行状态读档后重新生成即可。

## 11. 代码需求

需要支持：

- 读取 `data/helpers.json`。
- 记录已解锁帮手。
- 购买帮手并扣除现金。
- 购买成功时将新帮手默认设为上阵。
- 在全部场景生成所有已上阵帮手。
- 响应上下阵切换并刷新当前场景帮手。
- 帮手能寻找场景中的可收集产物。
- 帮手能移动到目标。
- 帮手能调用统一收益发放逻辑。
- 帮手收集后，目标从场景中消失。
- 场景切换时执行帮手进入和离开传送门的过场。
- 过场结束后重新寻找当前场景目标。

## 12. 验收需求

功能验收：

- 未解锁帮手时，场景里没有帮手。
- 购买热心邻居后，所有场景中都能出现热心邻居。
- 购买热心邻居后默认为上阵状态。
- 点击热心邻居右侧的 `下阵` 后，角色从场景中消失且停止拾取。
- 下阵后按钮变为 `上阵`，点击后角色重新进入场景工作。
- 退出并重新进入游戏后，帮手上下阵状态保持不变。
- 旧存档没有上阵字段时，所有已购买帮手默认上阵。
- 热心邻居会自动走向当前场景产物。
- 热心邻居靠近产物后能自动收集。
- 玩家获得帮手收集的收益。
- 从街道切换到酒吧时，所有帮手走进右侧传送门。
- 酒吧背景出现后，所有帮手从左侧传送门出来。
- 从酒吧切换回街道时，所有帮手走进左侧传送门。
- 街道背景出现后，所有帮手从右侧传送门出来。
- 帮手离开传送门后继续寻找当前场景产物。
- 快速重复点击场景切换按钮不会触发第二次过场。
- 帮手和玩家同时收集同一目标时，只结算一次。
- 场景中存在多个产物时，不同帮手不会同时走向同一个产物。
- 帮手的目标被玩家提前捡走后，该帮手会释放预约并寻找新目标。

手感验收：

- 帮手移动速度不能太快，避免抢走玩家所有操作感。
- 帮手收集频率要让玩家明显感觉到自动化收益。
- 帮手不能遮挡玩家主要点击区域。
- 帮手行为要看起来像“在场景里工作”，不是静态数字加成。

技术验收：

- 帮手配置来自配置文件。
- 帮手购买状态可以存档。
- 帮手收益使用统一收益发放逻辑。
- 新增帮手时，不需要改核心点击逻辑。
- Godot editor 加载无报错。
