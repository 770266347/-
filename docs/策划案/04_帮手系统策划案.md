# 04_帮手系统需求点

## 1. 系统目标

帮手系统负责决定：

> 玩家解锁帮手后，帮手会进入当前场景走动，并自动帮玩家收集场景中的回收物。

第一版帮手系统只做“自动走动 + 自动拾取”，不先做复杂 AI。

## 2. 帮手基础需求

- 玩家可以通过升级或购买解锁帮手。
- 解锁后的帮手会显示在当前场景中。
- 帮手会在场景区域内自动走动。
- 帮手会自动寻找可收集回收物。
- 帮手收集成功后，玩家获得对应回收物和现金。
- 帮手不能收集尚未解锁的产物。
- 场景切换后，帮手进入新场景继续工作。

## 3. 帮手行为需求

帮手第一版使用简单行为循环：

```text
待机 -> 寻找目标 -> 移动到目标 -> 收集目标 -> 继续寻找
```

### 3.1 待机

- 当前场景没有可收集目标时，帮手在场景内随机走动。
- 待机时可以播放轻微左右晃动或走路动画。
- 待机时间不需要太长，避免玩家觉得帮手没在工作。

### 3.2 寻找目标

- 帮手优先寻找距离最近的可收集产物。
- 如果没有目标，继续待机。
- 如果目标已经被玩家点击收走，帮手重新寻找目标。

### 3.3 移动到目标

- 帮手朝目标位置移动。
- 移动速度由帮手配置决定。
- 帮手不能走出可见场景区域。
- 帮手移动过程中不阻挡玩家点击。

### 3.4 收集目标

- 帮手靠近目标后自动收集。
- 目标被收集后消失。
- 玩家获得该目标对应收益。
- 出现飘字反馈。
- 帮手收集和玩家点击使用同一套收益发放逻辑。

## 4. 帮手解锁需求

- 每个帮手有独立解锁条件。
- 未解锁帮手不显示在场景中。
- 已解锁帮手不能重复解锁。
- 解锁成功后，帮手立即进入当前场景。
- 解锁状态需要存档。

第一版建议做 3 个帮手：

| 帮手 ID | 名称 | 解锁费用 | 定位 |
|---|---|---:|---|
| helper_neighbor | 热心邻居 | 80 | 新手帮手，移动慢，收集塑料瓶 |
| helper_cart | 小推车阿姨 | 350 | 中期帮手，移动较快，适合街道 |
| helper_bar_staff | 酒吧清洁员 | 1200 | 酒吧帮手，适合酒吧瓶子 |

## 5. 帮手能力需求

每个帮手需要配置：

- 帮手 ID
- 显示名称
- 解锁费用
- 移动速度
- 收集半径
- 收集冷却
- 可工作的场景
- 优先收集类型
- 视觉素材

推荐参数：

| 帮手 | 移动速度 | 收集半径 | 收集冷却 | 可工作场景 |
|---|---:|---:|---:|---|
| 热心邻居 | 80 pt/s | 24 pt | 1.2 秒 | 街道 |
| 小推车阿姨 | 110 pt/s | 28 pt | 0.9 秒 | 街道 |
| 酒吧清洁员 | 120 pt/s | 28 pt | 0.8 秒 | 酒吧 |

## 6. 场景适配需求

- 街道场景显示街道可用帮手。
- 酒吧场景显示酒吧可用帮手。
- 如果帮手不支持当前场景，场景切换后该帮手暂时不出现。
- 帮手切换场景后，需要重新寻找目标。
- 帮手在不同场景可以使用不同出生点。

第一版规则：

| 场景 | 可出现帮手 |
|---|---|
| 街道 | 热心邻居、小推车阿姨 |
| 酒吧 | 酒吧清洁员 |

## 7. 自动拾取规则需求

- 帮手只能拾取当前场景中已经生成的产物。
- 帮手不能凭空产出收益。
- 帮手收集目标后，该目标从画面中移除。
- 帮手和玩家同时点击同一个目标时，只能结算一次。
- 帮手拾取收益和玩家点击收益一致。
- 帮手拾取也会计入累计回收物和累计现金。

## 8. UI 需求

主界面下方显示页签栏。

页签栏包含：

- `升级`
- `帮手`

`帮手` 页签需要显示不同帮手的购买按钮。

帮手购买按钮需要显示：

- 帮手名称
- 解锁费用
- 当前状态
- 工作场景
- 简单能力描述

按钮尺寸要求：

- 按钮尽量小。
- 单个按钮高度不宜过高。
- 文案优先短句，避免把底部面板撑得太高。
- 竖屏下至少能同时看到 3 个帮手按钮。

帮手状态：

| 状态 | 显示含义 |
|---|---|
| 未解锁 | 可以购买或条件不足 |
| 已解锁 | 帮手已拥有 |
| 工作中 | 帮手正在当前场景工作 |
| 不在当前场景 | 已解锁，但当前场景不可用 |

## 10. 存档需求

存档中需要记录：

- 已解锁帮手 ID 列表
- 帮手是否已购买

不需要存档：

- 帮手当前坐标
- 帮手当前目标
- 帮手当前动画状态

这些运行状态读档后重新生成即可。

## 11. 代码需求

需要支持：

- 读取 `data/helpers.json`。
- 记录已解锁帮手。
- 购买帮手并扣除现金。
- 根据当前场景生成可工作的帮手。
- 帮手能寻找场景中的可收集产物。
- 帮手能移动到目标。
- 帮手能调用统一收益发放逻辑。
- 帮手收集后，目标从场景中消失。
- 场景切换时，重新刷新帮手显示。

## 12. 验收需求

功能验收：

- 未解锁帮手时，场景里没有帮手。
- 购买热心邻居后，街道中出现热心邻居。
- 热心邻居会自动走向街道产物。
- 热心邻居靠近产物后能自动收集。
- 玩家获得帮手收集的收益。
- 切到酒吧后，热心邻居不出现在酒吧。
- 购买酒吧清洁员后，酒吧中出现酒吧清洁员。
- 帮手和玩家同时收集同一目标时，只结算一次。

手感验收：

- 帮手移动速度不能太快，避免抢走玩家所有操作感。
- 帮手收集频率要让玩家明显感觉到自动化收益。
- 帮手不能遮挡玩家主要点击区域。
- 帮手行为要看起来像“在场景里工作”，不是静态数字加成。

技术验收：

- 帮手配置来自配置文件。
- 帮手购买状态可以存档。
- 帮手收益使用统一收益发放逻辑。
- 新增帮手时，不需要改核心点击逻辑。
- Godot editor 加载无报错。
